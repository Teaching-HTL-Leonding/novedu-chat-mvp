# Time-limiting a code

Output: teacher-docs/content/30-sharing-activities/03-time-limitation.md · order 3

Job: A teacher who wants a code to work only during a lesson or until a deadline. After
this chapter they can set a start and end time, know what students see outside the
window, and know that either bound is optional.

Cover:
- Setting a window: optional start and end times on the create or edit form, entered in
  your local time.
- What happens: before the start or after the end, the link does not open the activity
  and the student sees a clear message; during the window it works normally.
- Either bound is optional: no start means it opens right away; no end means it never
  expires.

Get right:
- You can change the window after creating the code.
- An expired code stays in your list, with its data, until you delete it.
- Times are entered in local time. If you mention where times are shown afterwards,
  verify it against the source rather than assuming.
- Describe the create/edit form; only mention CLI flags if cli/README.md documents them.

Look: docs/codes.md (the availability window), cli/README.md (any window flags).
